01 / ADAPT THE BUILT-IN WORKFLOW

Start with everything. Keep what you need.

The built-in workflow is an editable recipe. Narrow a component family or remove a strategy using the same operations as your own pipelines.

ADAPT THE PRESETPython
from iaml.flow import PipelineSpec
from iaml.steps import MaxAbsScaler, UnitNormScaler

pipeline = PipelineSpec.default()
pipeline.main.normalize.remove(UnitNormScaler, MaxAbsScaler)
pipeline.remove("minimal")

Edit IAML().pipeline directly, or prepare a recipe with PipelineSpec.default().

→IAML(pipeline=pipeline).fit(X, y)
THE DEFAULT PRESETmain + minimal

Two visible strategies, ready to train.

YOUR SEARCH SCOPEKeep the main strategy

Explore its normalizers, except UnitNormScaler and MaxAbsScaler. The minimal branch is removed.

YOUR TEAM'S FAMILIESDiscover, then subtract

normalizers() and predictors() gather registered methods into editable groups.

02 / COMPOSE THE RECIPE

Compose reusable methods.

Connect steps with >> and declare alternatives with choice. One recipe describes every permitted combination.

COMPOSE THE RECIPEPython
pipeline = (
    use(SimpleImputer).named("cleaning")
    >> choice(
        StandardScaler, RobustScaler,
    ).named("normalize")
    >> choice(
        LogisticRegression,
        use(RandomForestClassifier).named("forest"),
    ).named("models")
)

Aliases such as normalize and forest let you target these objects in later edits.

→IAML(pipeline=pipeline).fit(X, y)

06 / REUSE YOUR BUILDING BLOCKS

Write once. Adapt each study.

Share preparation fragments across model recipes. Each composition owns its copy; clone a complete recipe when a study needs its own changes.

FRAGMENTS AND COPIESPython
preparation = (
    use(SimpleImputer)
    >> choice(StandardScaler, RobustScaler).named("normalize")
)
linear = preparation >> use(LogisticRegression)
forest = preparation >> use(RandomForestClassifier)

forest_variant = forest.clone()
forest_variant.normalize.remove(RobustScaler)

The shared fragment and both original recipes retain their two normalizers.

→IAML(pipeline=forest_variant).fit(X, y)
REUSABLE PREPARATIONImpute → Standard or Robust

A shared fragment expresses your team's preparation policy.

TWO INDEPENDENT RECIPESLinear model · Forest model

Both receive a copy of the preparation fragment.

ONE TAILORED STUDYImpute → Standard → Forest

Removing Robust from the clone leaves every original recipe unchanged.

07 / ADD YOUR TEAM'S COMPONENTS

Your methods become reusable steps.

Implement the component interface, register your class and place it with use. Here, a study transformation adds a squared age feature before preprocessing.

A CUSTOM TRANSFORMATIONPython
@is_step("features_precleaning")
class AgeSquared(Actionable):
    name = "Squared age"
    def __init__(self):
        self.optimizable = False
    def suitable(self, dataset):
        return "age" in dataset.X.select_dtypes("number")
    def fit(self, dataset):
        return self
    def transform(self, X):
        return X.assign(age_squared=X["age"] ** 2)
pipeline.add(use(AgeSquared), before="cleaning")

Import Actionable from iaml and is_step from iaml.decorators.is_step. Keep reusable classes in an importable module such as study_components.py.

→IAML(pipeline=pipeline).fit(X, y)
Raw data→ Your AgeSquared step→ IAML preparation + model
PART OF THE AUTOML WORKFLOWFit within each training fold

IAML checks applicability, runs the step inside cross-validation and reuses it for prediction.

EXTENSIBLE THROUGHOUTBeyond transformations

Add predictors, resamplers, metrics, splitters, optimizers, statistics or plots through their corresponding interfaces.

08 / CONFIGURE THE WHOLE STUDY

Your study goes beyond the model.

Choose the summaries, scoring objective and explanations with the same component API. Each collection runs its applicable methods; calculation settings stay fixed.

ONE STUDY, THREE COLLECTIONSPython
analyses = dict(
    metrics=metrics(
        use(RecallMetric, pos_label=1).named("event_recall"),
    ),
    main_metric="event_recall",
    statistics=statistics(SummaryTableStatistic),
    explanations=explanations(
        use(KernelSHAP, nsamples=100).named("shap"),
    ),
)
study = IAML(pipeline=pipeline, **analyses)
summary = study.get_descriptive_statistics(X, y)

The alias selects the scoring objective. Descriptive statistics can run before any training.

BEFORE TRAININGDescribe your cohort

get_descriptive_statistics(X, y) computes the configured summaries of the supplied data.

DURING VALIDATIONOptimize event recall

event_recall ranks candidates. Other configured metrics keep their own scores and coverage.

AFTER FITTING, ON REQUESTExplain selected predictions

model.explain(X_test, y_test) runs the candidate's configured explanations. SHAP loads when requested.

09 / CONTROL THE SEARCH

Choose how IAML explores your recipe.

Set the optimizer, validation folds, evaluation budget and workers. A partial start changes the initial candidates while keeping the other declared alternatives available.

SEARCH SETTINGSPython
pipeline.models.start("forest")
search = IAML(
    pipeline=pipeline,
    optimizer=GeneticOptimizer,
    splitter=partial(kfold_splitter, nb_folds=3),
    max_duration=120,
    max_stage_duration=30,
    max_workers=2,
    keep_training_history=True,
    **analyses,
)

Shared analyses keep the study's objective and collections. A partial start requires GeneticOptimizer or another component-switching optimizer; start() restores a full start.

→search.fit(X, y)
INITIAL CANDIDATESForest
↓
PERMITTED MODEL ALTERNATIVESForest · Logistic
↓
SEARCH EXECUTION3 folds · 2 candidate workers

The 120-second search budget does not include all initialization and final fitting time. Validation records remain available in search.training_history.

10 / INSPECT AND SHARE

Make each iteration reviewable.

Inspect a recipe, compare changes and export its reconstruction code. Clones are independent; editing recipes prepares future runs while trained candidates keep their own definitions.

REVIEW A VARIANTPython
base = pipeline.clone()
variant = base.clone()
variant["forest"].configure(n_estimators=300)

print(variant.describe())
print(variant.diff(base))
code = variant.to_code()

Changing the starting value to 300 keeps the forest's 100–500 search domain. The base recipe keeps its original starting value.

DESCRIBEA readable, structured recipe

Inspect the tree, alternatives, initial values, domains and constants.

DIFFA concrete change to review

n_estimators: 200 → 300
The domain remains 100–500.

TO_CODEReconstruction code to share

Preserve aliases and active or retained domains. Code references importable components; it does not contain fitted model state.
